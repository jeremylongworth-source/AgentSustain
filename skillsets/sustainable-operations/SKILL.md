# Sustainable operations

Use the [operations contract](../../docs/operations-contract.md) and [dependency manifest](manifest.json) for the supported analytical composition. This development skillset connects existing atomic skills; it does not replace their measurement, provenance, factor or review contracts.

Start with the organizational/reporting boundary and source coverage. Execute only the needed allowlisted assessments in explicit dependency order. Keep energy service, waste cohorts/routing, water withdrawal/consumption/reuse, material stocks/flows and financial horizons distinct. For carbon-footprint questions, compose the sourced CO2e, separate scope accounts, selected inventory and emission-hotspot helpers before attributing benefits. Preserve missing categories and unrepresented loads; a selected emissions hotspot is not a full facility footprint. Fixture mode is explicit per step and supports invented evaluation factors only. Unknown costs and physical benefits remain data needs; do not infer tariffs, savings percentages or emission factors.

Retain supporting process observations, mechanisms, alternative explanations and service/quality constraints in domain interpretation results. Use interpretation_result_ids to connect those recorded assessments to each candidate; fresh arithmetic does not independently reproduce that reasoning.

Register evidence-linked candidates with a named or explicitly unassigned owner, declared interactions and proposed dated actions. Link a composed business case only when its applicability has been reviewed; retain pending financial/engineering decisions. Keep data gathering separate from implementation proposals, and expose unresolved reviews and missing ownership/quantification. When work depends on other proposed actions, give every action an ID and explicit depends_on links, including cross-domain evidence prerequisites. Use the returned sequence to expose prerequisites; it does not establish completion, resource availability or investment priority. No action is executed or authorized by this workflow.

The CLI returns one checked batch state proposal, preserving each source result, original state/history and all open gaps/reviews. It writes no state file, changes no production system and sends no external message. The manifest is a development dependency inventory; independent behavioral evaluation and later routing/skillset release review remain pending.
