# Carbon-accounting specialist workflow

The draft `carbon-accounting` skillset composes nine existing carbon operations through `scripts/carbon_workflow.py`, reusing the unchanged dispatch in `scripts/operations_tools.py`. The [manifest](../skillsets/carbon-accounting/manifest.json) references actual atomic entrypoints reviewed through 7fff776. It is a development dependency inventory; the subsequent specialist interface and manifest await separate scoped owner review. No router activation, installation or release follows.

Use the common input envelope with `skill=carbon-accounting` through `python -m scripts.run_carbon_workflow request.json`. Exact parameters are `steps`, `outputs`, `accounting_review`, `result_id`. The runner produces an atomic candidate at original revision +1, retaining every intermediate analytical result/domain link and its original evidence, metric metadata, uncertainty, gaps and reviews. It modifies no input object, state file or external service. Exit 0 can carry a blocked or partial analytical outcome; exit 2 identifies an invalid envelope, graph or structural request.

Each nonempty step is exactly `{skill, parameters, depends_on}`. `parameters` uses the existing helper's exact fields and fresh `result_id`, with optional boolean `fixture_mode` defaulting to false. Supported operations are CO2e calculation, direct Scope 1, separate location/market Scope 2, Scope 3 classification/category calculation, selected inventory composition, comparison and emission hotspots. No raw gas/statutory ledger conversion, factor/GWP default, new domain formula, arbitrary code or recursive specialist invocation is added. Synthetic sources require explicit opt-in on every relevant step.

Prerequisites reference fresh result IDs within the batch, form an acyclic graph and are evaluated in deterministic input order among ready branches. Explicit current result selectors and known single-subtotal metric selectors must name their producer as an ancestor. Result and metric references use separate namespaces: an existing scope account whose result ID matches a newly produced quantity's metric ID remains that original account, not an implicit dependency on the new quantity. Actual resolved produced-metric ownership is checked again before execution. Planned subtotal metric IDs cannot collide with existing metrics or batch result IDs. Prior comparison snapshots remain separate and are handled by the existing comparison method, including lineage retention; the workflow does not pretend a prior-state source is a newly produced current source.

A blocked/invalid explicit prerequisite prevents helper invocation. A blocked common result retains exact step inputs, source evidence, inherited gaps/reviews and `CARBON_DEPENDENCY_BLOCKED`; missing factors propagate as `EMISSION_FACTOR_REQUIRED`. Independent branches continue. Domain-input errors from an invoked helper become visible `CARBON_STEP_INPUT_REQUIRED` blocked results, preserving other analyses; graph/selection errors do not issue a candidate state. Partial sources can enter downstream methods, which must recheck their accepted contributions and retain missing coverage. A partial known subtotal is not silently changed to a full inventory or zero. No supported step makes an all-blocked batch successful: its aggregate stays blocked.

`outputs` has exact keys `inventories`, `hotspots`, `comparisons`, each a distinct list of freshly requested results of that method. The report retains each selected result, including blocked outputs with no metric. Multiple location/market inventories stay separate alternatives. Scope accounts, leaves, inventory totals and hotspot shares are not added again; `combined_inventory_total` is always null and the aggregate emits no metric. Comparable observed changes retain their periods and original comparability review, without project attribution or emissions-reduction verification.

`accounting_review` requires exact `boundary_id`, `period`, `evidence_ids`, `scope`, `rationale`, `reviewer_role`, `coverage_complete`. Boundary/period must match validated state; evidence must resolve and text/coverage declarations must be explicit. These attributed observations do not authenticate source fitness, completeness or reviewer expertise. Declared incomplete coverage adds a gap. Declared complete coverage never sets `coverage_complete_authenticated=true`; actual component/category gaps survive. Open professional and assurance reviews are registered after source execution; existing legal, engineering, assurance and other obligations are retained without resolution.

`CARBON_ACCOUNTING_WORKFLOW` records ordered step IDs, dependency/helper-invocation/status/metric trace, separate selected source outputs and review declarations. `CARBON_ACCOUNTING_INPUTS` preserves exact parameters. Intermediate source results remain in history with complete reports. Completed aggregate status, when applicable, describes only successful selected analytical steps; it establishes no organization-wide inventory, scientific authentication, statutory total, assurance, project reduction or publication approval. Those report flags remain false.

The [fictional specialist evidence](../evaluations/sus22-carbon-accounting.md) includes separate 500/500 location/market subtotals, missing-factor blocks with independent supported calculation, legacy 725 partial Scope 1/2/3 inventory replay and observed -100/-20% comparison. These are supplied synthetic examples, with missing coverage and professional reviews intact. Actual source/method/rights evaluation, broader accounting methods, independent organization and behavioral evaluation, specialist/router approval and public-v1 readiness remain open. This increment does not close SUS-22 or the full roadmap goal.
