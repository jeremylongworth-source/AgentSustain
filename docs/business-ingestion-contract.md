# Pinned business CSV ingestion

`business-csv-ingestion-0.1.0` adds `ingest-business-records` through `python -m scripts.run_business_ingestion request.json`. It returns a common `normalize-sustainability-data` result and append-only candidate state. This subsequent source interface awaits scoped owner review; it does not change the shared schemas, existing manager/calculation methods or source-review authority.

Exact parameters are `file_pin`, `source_metadata`, `fixture_mode`, `result_id`, `document_evidence_id`. The pin has `path`, `sha256`, `source_version`, `synthetic`. The path selects a `.csv` under workspace `data/inputs/`; traversal, escaping links, unselected bytes and files over 1 MiB are blocked. `source_metadata` contains explicit `title`, `publisher`, `accessed`, `tier`, validated with the common evidence schema. These are supplied declarations, not publisher authentication. Synthetic input requires explicit boolean fixture opt-in; the recognized shipped fictional export cannot be relabeled ordinary data, including an identical byte copy under another name. The secondary recognized-fixture lookup also checks its resolved workspace boundary and size before reading; synthetic requests do not need that lookup. Other files' synthetic declarations remain unverified source metadata.

The exact UTF-8 header is `record_id,evidence_id,metric_id,name,value,unit,period_start,period_end,boundary_id,geography,kind,assumption,uncertainty_kind,uncertainty_description,uncertainty_value,uncertainty_unit,notes`. There are 1–200 complete logical records, with distinct fresh row/evidence/metric identities and a fresh document evidence ID. IDs, name, declared unit/geography, current boundary and uncertainty description must be nonblank. Ragged/extra cells, unexpected/duplicate headers, invalid dates or schema-invalid uncertainty block the entire file. No partial records, new assumptions or row evidence survive a blocked import. Existing input history remains intact.

Values use explicit ASCII decimal/scientific notation, without comma/underscore locale guesses, formulas, NaN, infinity or hidden whitespace. Blank quantity cells become null with a gap. Signed values are preserved for subsequent domain review; physical helpers continue to enforce their own nonnegative constraints. Overflow or nonzero-to-zero underflow blocks ingestion. The exact numeric literal and complete row stay in the source report; finite JSON number representation is disclosed without pretending arbitrary decimal precision is preserved in a float. Units are never inferred or converted.

Record `kind` is `measurement`, `model_input`, `assumption` or `unknown`. Model/assumption rows require substantive explicit assumption text and are not observations. All kinds remain attributed, with `kind_authenticated=false`. Uncertainty kind/value/unit follow the common schema; unknown uncertainty is not assigned zero. Notes, including multiline instructions asking for publication or review removal, are retained as inert source text. The report records logical ordinal and record-specific physical end line, avoiding confusion between CSV records and text lines.

A document evidence record identifies the exact pinned file/version, declared period range, row geographies and mixed row units. Every row evidence record points to `workspace:<path>#record=N`, preserves its own unit/period/geography/uncertainty and references the document through calculation lineage. Each metric directly references its own row evidence; the document remains its ancestor, rather than making every distinct row look like duplicate measurement coverage to existing helpers. The aggregate resolves all new evidence, preserves the exact parsed rows in `CSV_ROW_SOURCE`, and retains exact parameters in `BUSINESS_INGESTION_INPUTS`. No source authenticity, measurement fitness or organization completeness is inferred from byte identity or tier declarations.

The successful import stays partial, registers an open professional source/data review and retains a source-fitness gap. `raw_business_data_ingestion_performed=true` means these selected CSV bytes were read and parsed; it grants no source authentication or downstream readiness. Existing evidence, factors, results, domain references, assumptions, gaps and reviews remain unchanged except append-only additions. No factor or GWP is registered, guessed or derived from model memory. Downstream emissions still require separately supplied defensible factors and return `EMISSION_FACTOR_REQUIRED` when unavailable.

[The raw-source workflow evidence](../evaluations/sus23-business-source-workflow.md) links an actual pinned 18-record fictional CSV import to the existing manager CLI using its exact candidate state. The CSV and request files are unchanged. Known physical/source quantities, separate monetary assumptions, future targets, partial inventories and open reviews survive both steps. The manager's own ingestion flag remains false because that helper consumes already-normalized state; the preceding importer records the actual raw-file step. No existing historical manager capture or contract is silently migrated. This first bounded export format does not establish bill/PDF/spreadsheet extraction, all organizational data coverage, source authenticity, independent agent reliability, actual framework/jurisdiction completeness, scoped approval or public-v1 readiness. The full roadmap goal remains active.
