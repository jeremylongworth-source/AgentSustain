# Climate-risk screening contract

The roadmap's SUS-16 development wave now has twelve initial physical, transition and register helpers. These do not complete the fourteen named climate-risk workflows. Broader physical/transition methods and organization-level register/prioritization/resilience methods remain to implement and evaluate. The taxonomy's SUS-10 family code and the development wave's SUS-16 code are distinct.

## Method orientation and sources

The [IPCC AR6 WGII Annex II glossary (2022)](https://www.ipcc.ch/report/ar6/wg2/chapter/annex-ii/) treats exposure as presence in potentially affected settings and distinguishes vulnerability from exposure. Its risk concept involves hazard, exposure and vulnerability interactions. This supports keeping these records separate; it supplies no site-specific data, risk score or damage function here. Verified through the indexed official text on 2026-10-05; direct page/PDF retrieval returned 403, so no full-text review or local source copy is claimed.

[OGC API Features Part 1 Core (17-069r4)](https://docs.ogc.org/is/17-069r4/17-069r4.html) specifies CRS84 longitude/latitude order. The helper explicitly requires `OGC:CRS84`; it does not treat an unspecified WGS84/EPSG identifier as equivalent. The coordinate implementation below is a repository screening choice, not an OGC hazard methodology or disclosure standard. Hazard provider data, resolution, versions, licensing and applicability must be inspected for each real use; no hazard dataset or provider permission is bundled.

## Execution and common review

`python -m scripts.run_climate request.json` reads the existing `input.schema.json` envelope. `run_climate(state, skill, parameters)` emits a result and checked append-only proposal. It never writes shared state, contacts providers or geocodes addresses. Shapes of evidence, metrics, state and results are unchanged. Every prior result, source, assumption, gap and review survives. Fresh result IDs are mandatory.

Both operation reviews require `confirmed: true`, current nonempty `evidence_ids`, substantive `reviewer_role`, `rationale`, `scope`, `selection_basis`, `limitations`, matched `boundary_id` and reporting `period`, ISO `as_of_date`, boolean `coverage_complete`, and `exclusions` as an explicit list of nonempty strings. `confirmed` records the caller's source review, not professional approval. Hazard review method is `source_hazard_register`; mapping review method is `bounding_box_screen`. Mapping uses the same selected scope and an as-of date no earlier than the selected hazard review. Reporting period, climate baseline, hazard horizon, source observation and asset operating period retain their separate meanings.

Every successful execution adds an open qualified climate/site/dependency professional review. `completed` means the selected record was executed without recorded gaps; it does not mean approved, comprehensive or model-validated. Conditional inputs produce `partial`, structural contradictions produce `blocked`; unknowns are never zero. Selected dependencies or quantity ancestry with unresolved factors preserve `EMISSION_FACTOR_REQUIRED`. There are no emission calculations. Only exposure may emit a conditional supplied-stock percentage; the other current operations add no numerical metrics. Blocked executions discard all new metrics, including any calculated before a later invalid observation.

## Identify climate hazards

Parameters are exactly `hazards`, `hazard_review`, `result_id`. Each hazard contains exactly `id`, `name`, `physical_type`, `mechanism`, `context`, `spatial_extent`, `evidence_ids`, `evidence_fit`, `source_fragment`, `observed_date`, `limitations`. IDs are distinct; required descriptions are substantive; `physical_type` is `acute` or `chronic`. Transition policy/market/technology/reputation pathways belong to separate workflows.

`context` contains exactly `kind`, `scenario`, `model`, `baseline_period`, `horizon`. Periods are explicit ISO start/end objects. `projected` requires a named supplied scenario and model and a horizon starting after its baseline ends. No scenario is supplied by the helper. `observed` requires null scenario/model and equal baseline/horizon ending no later than the review date. Historical observations do not establish future projections, attribution or probabilities.

Evidence IDs are distinct current records, possibly empty for unsupported candidates. `evidence_fit` is `reviewed_supporting`, `unverified` or `irrelevant`. `observed_date` is the date of the cited source observation/applicability record, not an invented hazard event date; it is ISO or null and cannot postdate review. Source support is only a `reviewed_source_candidate` when evidence, declared supporting fitness, observation within every cited evidence period, and known source versions are present. Otherwise it stays `unverified` with a gap. Full original evidence metadata, assumptions and uncertainty accompany the record. Arbitrary source prose or a fitness flag cannot authenticate the scientific truth of the claim.

`spatial_extent` is null or exactly `crs`, `bounds`, `representation`, `resolution`. Supported representation is `bounding_box`, CRS is `OGC:CRS84`, bounds are four finite numbers `[west, south, east, north]` in degrees, longitude within -180..180, latitude within -90..90, west <= east and south <= north. Zero-width boxes can represent a selected point/line; no area is inferred. Resolution is a substantive supplied description. A box represents the selected source extent, which may be a coarse grid or study region rather than an inundation footprint. Missing extent stays unknown. Antimeridian-crossing boxes require specialist geometry handling and are blocked; no reprojection, polygon/terrain intersection, geodesic area, interpolation or default hazard intensity is provided.

The `CLIMATE_HAZARDS` diagnostic retains all selected source contexts and review sources; probability, asset damage and risk score remain null, climate attribution/model validation and public-claim authorization remain false. Empty lists and exclusions cannot establish hazard absence or full coverage.

## Map assets to hazards

Parameters are exactly `hazard_result_id`, `assets`, `comparisons`, `mapping_review`, `result_id`. The current nonblocked hazard result must replay completely against source state, including full evidence metadata. Changed source version, location, period, uncertainty or input context invalidates dependency reproduction; old records are never rewritten.

Each asset contains exactly `id`, `name`, `asset_type`, `boundary_relation`, `facility_id`, `function`, `owner`, `location`, `operating_period`, `evidence_ids`, `evidence_fit`, `source_fragment`, `observed_date`, `limitations`. Distinct IDs and substantive descriptions are required. Type is `physical_asset`, `service_dependency`, `people_group` or `ecosystem`. Direct assets require a facility in the selected organizational boundary; external `value_chain` dependencies require null facility ID and do not imply control or consolidation. Location has the same box/null structure above. The location box can describe uncertain positional extent and must retain its resolution/limitations. Operating period is explicit ISO start/end or null, not copied from the historical reporting period or future hazard horizon. Source fitness/version/date support uses the hazard rules; no verified future presence or operating continuity is inferred.

Each comparison contains exactly `asset_id`, `hazard_id`, `evidence_ids`, `spatial_fit`, `context_fit`, `rationale`. It must refer to known assets/hazards and include all their actual evidence IDs. Pair review separately declares spatial and scenario/horizon fitness using the three evidence-fit values. Pairs are unique. Omitted selected pairs create gaps rather than automatic judgements.

Closed-box intersection includes an edge or corner touch. `candidate_spatial_relation` is `intersects_selected_boxes`, `outside_selected_box` or `unknown`. No degree-space area or fraction is calculated. Operating/hazard windows use inclusive interval overlap, yielding `overlapping`, `not_overlapping` or `unknown`. These relations are disclosed even when source fitness is withheld, as candidate arithmetic only.

`screening_status` is `unverified` unless both source candidates, known boxes/operating window, substantive paired evidence, and separately supporting spatial/context review are present. Supported overlapping windows yield `possible_exposure_candidate` for intersecting boxes or `outside_selected_extent_screen` otherwise. Disjoint windows yield `no_documented_temporal_overlap`. Possible overlap always retains a site/dependency investigation gap: a regional grid's envelope does not establish actual flooding, heat stress, disruption, causal climate attribution or loss. Outside the selected extent and no documented temporal overlap do not establish safety, absence of other hazards or asset availability. Unknown dates/coordinates/source fit cannot become a negative result.

The `ASSET_HAZARD_MAP` retains the complete hazard snapshot, asset sources and pair-review sources, including all resolution, limits and uncertainty. Exposure verification, asset/organization safety, model validation, implementation and claim authority remain false; vulnerability, probability, damage and risk scores remain null. Mapping is one input to subsequent exposure/vulnerability investigation, not a substitute for them or an organization-level climate-risk register.

## Assess exposure

Parameters are exactly `mapping_result_id`, `observations`, `exposure_review`, `result_id`. The mapping and its hazard parent replay fully against current sources, including input contexts, source metadata and metrics. Review method is `sourced_exposure_stock`, with the same scope and a current dependency review date.

Each observation contains exactly `id`, `asset_id`, `hazard_id`, `channel`, `mechanism`, `status`, `observed_date`, `evidence_ids`, `evidence_fit`, `source_fragment`, `limitations`, `quantity`. IDs are distinct; pairs must already be selected mapping comparisons. Channels are `direct_site`, `service_disruption`, `ecosystem_dependency`, `workforce_health`; statuses are `documented`, `proposed`, `unknown`, `conflicting`. Substantive mechanism, source fragment and limitations are required. Source/date/version support follows hazard rules. A documented supported observation linked to a `possible_exposure_candidate` mapping yields a `source_exposure_candidate`; other observations stay unverified. Source attribution remains conditional and does not verify actual site exposure.

`quantity` is null or exactly `amount_metric_id`, `total_metric_id`, `basis`, `scenario`, `model`, `stock_definition`, `service_scope`, `quantity_review`. Never infer quantity or fraction from bounding-box overlap, addresses, hazard intensity, floor area or a region's value. Select actual current sourced metrics with nonnegative exposed amount no greater than total. Units, periods and selected boundary must match exactly; unknown, percentage, index or dimensionless units are not stock units. No unit, currency or service conversion is inferred. Each quantity retains its full metric, calculation, units, period, assumption and uncertainty snapshot.

`historical_stock_proxy` requires the current reporting period and null scenario/model: its share is a declared historical proxy, not future stock, population growth or a forecast. `scenario_stock` requires a projected hazard, matching supplied climate scenario, named stock model, and a stock period wholly within that hazard horizon. A stock model is distinct from the climate model. Each selected stock quantity needs actual cited source-period coverage; relabeling past stock metrics as a future projection with historical source periods withholds the share. Source IDs and declared fitness cannot authenticate arbitrary model prose or forecast validity.

Quantity review contains exactly boolean `confirmed`, `evidence_ids`, `rationale`, `population_basis`, boolean `coverage_complete`, `source_contexts`. Source contexts are keyed by exactly the selected metric IDs; each is exactly `evidence_ids`, `evidence_fit`, `rationale`, `stock_definition`, `service_scope`. They must cite that metric's actual evidence, include it in the quantity review, and match the supplied population/service definitions. A physically compatible unit alone cannot equate shift observations, unique people, inventory stock, throughput or asset valuations. Inspect actual raw source population and time bases; withhold source fitness when they differ. Unknown quantities use null, not guessed amounts or zero. Irrelevant/unverified quantity fit, incomplete exposure support or unsupported map context produces no accepted metric.

For supporting comparable sourced stock under a documented candidate, the helper emits `amount / total * 100` in `%`, using Decimal precision 34 and the stock's period. This is neither hazard probability, expected loss, nor a verified exposed fraction of the organization. A sourced zero total leaves the percentage undefined; a known zero amount with positive total can produce zero share without safety inference. Incomplete stock coverage and historical proxies retain gaps. All channels/hazards stay separate: shared stock must not be summed, and organization totals remain null. `CLIMATE_EXPOSURE` retains the complete map/source/stock snapshots; exposure verification, future-stock verification, organization safety and claim authority remain false.

## Assess vulnerability

Parameters are exactly `exposure_result_id`, `rubric`, `factors`, `vulnerability_review`, `result_id`. The current exposure result and its entire map/hazard/quantity chain replay fully. Review method is `sourced_condition_profile`, same selected scope and current review date; substantive `rubric_fit_rationale` is required. The [IPCC AR6 WGII Technical Summary (2022)](https://www.ipcc.ch/report/ar6/wg2/chapter/technical-summary/?lang=en) distinguishes susceptibility and capacities to cope/adapt; indexed official text checked on 2026-10-05 supports separate condition dimensions, not a default company score or engineering tolerance.

Rubric contains exactly `id`, `name`, `version`, `evidence_ids`, `evidence_fit`, `criteria`. Supporting known-version sources and supporting rubric fitness are required; unsuitable rubric blocks profiling. Each criterion is exactly distinct `id`, `dimension`, substantive `requirement`. Dimensions must include `sensitivity`, `coping_capacity`, `adaptive_capacity`. There is no default numerical scale, no summation and no inference that stronger capacity cancels a sensitive condition.

Each factor contains exactly `id`, `exposure_id`, `criterion_id`, `status`, `effect`, `cause_effect`, `effective_period`, `observed_date`, `evidence_ids`, `evidence_fit`, `source_fragment`, `limitations`. IDs and exposure/criterion pairs are distinct and current. Status is `condition_observed`, `capacity_demonstrated`, `planned`, `unknown`, `conflicting`; effect is `susceptibility_increasing`, `susceptibility_reducing`, `unknown`. Substantive causal interpretation must connect the selected service/people/ecosystem susceptibility or capacity to the actual hazard mechanism, not a generic resilience claim. `capacity_demonstrated` is for coping/adaptive dimensions, not a replacement for sensitivity. Keep exact raw source qualifiers and contrary evidence; observed effect is source-attributed, not a causal proof.

Effective period is explicit ISO start/end or null. Observation date has the same source-period and review-date rules as earlier operations. A `sourced_condition_candidate` requires supporting source/date/version, an observed condition or demonstrated capacity, a declared effect, a period covering the full selected hazard horizon, and a supported exposure candidate. This tests the supplied applicability claim, not actual future capacity. A current test or inspection does not automatically supply a lifetime through 2050. Null/partial effective coverage, plans, conflicts, unknowns and unverified exposure leave the assessment unverified; current source observations stay visible alongside horizon limits. Plans never become exercised coping or implemented durable adaptation.

Profiles retain each dimension separately. All its selected criteria need candidate conditions to yield `reviewed_criterion_candidates`; omissions or unsupported conditions yield `conditions_unresolved`. Missing criteria generate gaps without assuming capacity or susceptibility. `CLIMATE_VULNERABILITY` preserves all original exposure quantities, sources, criteria, causal conditions, uncertainty and open reviews. Vulnerability/organization scores and risk reductions remain null; capacity verification, safety, implementation and public-claim authority remain false. This initial qualitative condition profile supports later qualified risk/scoring investigation; broader susceptibility functions, tested capacity effectiveness and independent organization evaluation remain open.

## Score physical risk

Parameters are exactly `vulnerability_result_id`, `model`, `ratings`, `risk_review`, `result_id`. The current vulnerability/exposure/map/hazard/stock chain must fully replay. Review method is `ordinal_matrix_screen`, with matched scope/current date and substantive `model_fit_rationale`. The [IPCC AR6 WGII Summary for Policymakers (2022)](https://www.ipcc.ch/report/ar6/wg2/chapter/summary-for-policymakers/) identifies risk considerations involving consequences, likelihood, timing and ability to respond. Indexed official text checked on 2026-10-05 supports retaining these distinctions; it does not prescribe or endorse this repository's company-screening matrix, thresholds or classes.

Model contains exactly `id`, `name`, `version`, `evidence_ids`, `evidence_fit`, `likelihood_levels`, `consequence_levels`, `risk_levels`, `cells`. Supporting known-version sources and supporting model fitness are mandatory. The three nonempty ordered axes ascend from lower to higher likelihood, consequence and risk; each level is exactly distinct `id`, substantive `label`, `definition`. There is no default scale or multiplication of ordinal numbers. Each cell is exactly `likelihood_id`, `consequence_id`, `risk_level_id`. Every likelihood/consequence combination must appear once with known level IDs; no missing-cell inference. Increasing either axis cannot decrease the supplied risk order. Other model shapes require separate reviewed methods.

Each rating is exactly distinct `id`, current `exposure_id`, substantive `consequence_pathway`, `likelihood`, `consequence`, `context_review`. One rating per selected exposure observation; omitted observations stay gaps, not low risks. Each axis rating contains exactly `lower_level_id`, `upper_level_id`, `evidence_ids`, `evidence_fit`, `observed_date`, substantive `rationale`, `source_fragment`, `limitations`. Bound IDs are from the selected axis or null. Reversed/unknown IDs block. Supporting source/date/version and both known bounds are needed to use a finite interval; unknown or unverified bounds yield no finite classes. Never use stock percentage, regional cell frequency or unsupported engineering assumptions as consequence probability.

Context review is exactly boolean `confirmed`, `evidence_ids`, `exposure_fit`, `vulnerability_fit`, `scenario`, explicit `horizon`, substantive `rationale`. It must retain actual selected exposure and factor evidence, the exact selected climate scenario and horizon, and separate candidate fitness for both input kinds. Withheld context or unverified exposure prevents classification. Supporting review of conditional candidates is not a professional validation of capacity; unresolved vulnerability dimensions stay explicit and generate further gaps.

For supported supplied rating intervals the helper looks up all Cartesian combinations, retaining exactly their possible risk-level IDs in supplied order, lower/upper possible classes and no selected class. These combinations are an uncertainty screen, not joint event probabilities or a calibrated loss model. Noncontiguous possible classes stay noncontiguous; there is no interpolation, averaging or best-case selection. `conditional_matrix_screen` always retains qualified review and input-condition gaps; unsupported cases remain `unclassified`. A low-likelihood, severe-consequence cell is whatever the sourced matrix supplies, not automatically low risk. Hazard probability, expected loss, risk verification, acceptance and safety are not inferred. `PHYSICAL_RISK_SCREEN` preserves the full upstream snapshot, definitions, matrix, source observations, ranges and uncertainty; organization score stays null.

## Identify adaptation options

Parameters are exactly `risk_result_id`, `options`, `adaptation_review`, `result_id`. The current physical-risk result and every upstream dependency replay fully. Review method is `sourced_adaptation_candidates`, matched scope/current date. The [IPCC AR6 WGII Chapter 17 (2022)](https://www.ipcc.ch/report/ar6/wg2/chapter/chapter-17/) discusses response side effects, trade-offs and changing adaptation effectiveness; indexed official text checked on 2026-10-05 motivates preserving potential maladaptation, residual uncertainty and monitoring. It does not approve any option or site design here.

Each option contains exactly `id`, `name`, `kind`, `target_links`, `mechanism`, `intended_effect`, `effectiveness_limitations`, `residual_risk_basis`, `owner`, `timing`, `prerequisites`, `evidence_ids`, `evidence_fit`, `observed_date`, `source_fragment`, `limitations`, `constraints`, `trade_offs`, `monitoring`. Distinct IDs and substantive descriptions are required; kind is `investigation`, `physical_change`, `operational_change`, `ecosystem_action`. Source/date/version support yields a source option candidate, never an approved or implemented action. An unclassified risk can still motivate investigation; it cannot establish efficacy or priority.

Each target link is exactly a current distinct `risk_id` and distinct known `criterion_ids` from the parent vulnerability rubric. Empty criterion targeting retains a gap. Untreated selected risks remain gaps without risk acceptance. Mechanism and intended effect must connect the actual risk/service/condition; missing engineering tolerance, future presence, capacity or effectiveness cannot be invented. Owner is a proposal, not actual acceptance. Effectiveness and residual-risk descriptions retain uncertainty; expected reductions and residual-risk values stay null.

Timing is explicit inclusive ISO start/end or null. Unknown/overdue proposals remain unverified. Completion after hazard-horizon start retains missing early-period protection; completion beyond horizon end cannot establish in-horizon protection. Prerequisites are distinct current nonself option IDs, cycle-free; known prerequisite work must finish before dependent work starts, with shared endpoint days treated as overlap. This checks only supplied ordering, not resource availability, actual completion, scheduling feasibility or optimized plans.

Constraint and trade-off lists are explicit, possibly empty but gapped. Each observation is exactly distinct `id`, substantive `description`, `affected_party`, `status`, `evidence_ids`, `evidence_fit`, `observed_date`, `source_fragment`, `limitations`. Status is `identified`, `unmet`, `unknown`; identified source-attributed side effects are candidates, not measured harm, while unmet/unknown conditions remain unresolved. Source support follows prior rules. Preserve affected-party/runoff/ecosystem/workforce consequences separately; do not net benefits against possible harms or treat no observations as no maladaptation/complete feasibility.

Monitoring is null or exactly substantive `definition`, `owner`, `frequency`, plus `evidence_ids`, `evidence_fit`, `observed_date`, `source_fragment`, `limitations`. It is always a proposal; no measured performance or started monitoring is inferred. Every option adds an open engineering/affected-party/effectiveness/cost/resource/funding/owner investigation gap. `ADAPTATION_OPTIONS` retains all risk snapshots, source limits, constraints, trade-offs and prerequisites. Status is `proposed_pending_review`, preferred option stays null, and effectiveness, risk reduction, residual-risk resolution, funding, resource reservation, owner acceptance, implementation, resilience and public claims remain unverified or unauthorized. Broader response design, quantitative effectiveness, financial/resource composition and independent organization evaluation remain open.

This core contract does not implement IFRS disclosure requirements, incorporate subsequent amendments, determine materiality or assert reporting conformance. Source fitness, observation dates and known-version checks follow common rules; source-supported rows become `source_transition_candidate`, others `unverified`. Neither authenticates the source or verifies organization exposure. Mechanism must retain the actual transition/service causal concern and uncertainty; owner is proposed, not accepted.

## Build climate-risk register

Parameters are exactly `physical_results`, `transition_results`, `entries`, `interactions`, `register_review`, `result_id`. Source result lists are distinct current `score-physical-risk` and `assess-transition-exposure` IDs. Every complete current report, metric and declared evidence-ID lineage must replay against its nested source chain; altered lineage cannot be relabeled as review evidence. Selected missing-factor obligations propagate. Empty assessment families retain unknown coverage. Register review method is `source_climate_register`, matched organizational boundary/reporting period and no earlier than any selected source review. Its register scope may include different source scopes; it must preserve them separately, not relabel them as organization-wide evidence.

Review additionally supplies `source_contexts`, exactly keyed by every selected result ID. Each context is exactly substantive original `scope`, actual selected result `evidence_ids`, `evidence_fit` (reviewed_supporting/unverified/irrelevant), substantive `rationale`. Scope and evidence must exactly match the selected source. Withheld inclusion fitness retains the source without verified organization coverage; a metadata match cannot authenticate source applicability.

Each entry is exactly distinct `id`, current `source_result_id`, `source_record_id`, substantive `interpretation`, `owner`, `follow_ups`, `evidence_ids`, `evidence_fit`, `observed_date`, `source_fragment`, `limitations`. One entry per actual source record; duplicate counting and invalid references block. Sources/date/version follow common rules. Kind and characterization derive from the selected parent: physical class ranges/conditions versus transition causal observations. The helper retains the entire source snapshot, original characterization, source scope and actual evidence IDs. Interpretation has separate source fitness; it cannot replace or promote source findings.

Owner is exactly substantive `name`, `evidence_ids`, `evidence_fit`, `observed_date`, `source_fragment`, `limitations`. Source support yields an owner candidate only; actual acceptance is always false. Follow-ups are an explicit list, possibly empty with a gap. Each is exactly globally distinct `id`, substantive `action`, `owner`, `target_date`, `evidence_ids`, `evidence_fit`, `observed_date`, `source_fragment`, `limitations`. Target is an ISO date or null; unknown/overdue dates retain gaps, never completion. Each stays proposed_pending_review, without accepted ownership, started/completed work or implementation authority. Follow-ups are investigation/response proposals, not adopted adaptation or funded implementation.

Interactions are an explicit list; empty retains unassessed coupling/independence. Each is exactly distinct `id`, at least two distinct current `entry_ids`, `kind` (common_driver/shared_asset/dependency/response_tradeoff/unknown), substantive `mechanism`, `evidence_ids`, `evidence_fit`, `observed_date`, `source_fragment`, `limitations`. Source observations remain hypothesis_pending_review; scenario compatibility, interaction effects and double counting need qualified review. No joint probability or aggregate effect follows. `source_usage` records actual source plus interpretation evidence across entries; shared sources remain non-additive, not independent observations.

`CLIMATE_RISK_REGISTER` retains complete current parent snapshots, entries, proposed follow-ups, interaction hypotheses, review sources and all historical obligations. Source-record omissions remain unknown; every entry adds owner/source/qualified-review gaps.
