# Original inventory-comparison claims

`assess-comparison-claim-evidence` adds the draft `claim-comparison-0.1.0` source bridge and `claim-evidence-0.4.0` report. The common input contains the eight bound-material parameters plus `comparison_review`; run it with `python -m scripts.run_claims request.json`. This interface follows approved d99a70b and needs scoped review alongside the subsequent material/inventory interfaces. Earlier operations and captures retain their behavior.

`comparison_review` has exact fields `comparison_result_id`, `prior_state`, `prior_inventory_review`, `current_inventory_review`, `as_of_date`, `evidence_ids`, `evidence_fit`, `interpretation`, `quantity_interpretation`, `rationale`, `reviewer_role`. Each inventory review follows the [inventory source contract](inventory-claim-method.md) for its own reporting period. The prior snapshot is explicit, and its gaps, reviews and assumptions must survive in current state. The existing comparison method additionally checks preserved prior accounts/components/factors/evidence, the same organization, boundary and declared GWP basis, selected source/category/method coverage, comparable nonoverlapping periods and an evidenced comparability/change review. No prior stock is inferred from current data.

Both inventories are reproduced with complete accepted-leaf/account/inventory metrics, uncertainty, method/report and evidence lineage before the selected comparison is reproduced. All absolute/percentage metrics, current period/boundary, calculation inputs and the original comparison report must match; only verification metric IDs are normalized. Missing/changed factors remain `EMISSION_FACTOR_REQUIRED`. Other incompatible sources block with `CLAIM_COMPARISON_REQUIRED`. Original material and qualifiers still require exact byte/character binding. A claim always needs a quantity criterion in this path; comparative claims also need baseline and comparability criteria. Baseline/comparability observations refer to the reproduced paired records and remain supplied judgments, not independent semantic inspection.

`interpretation` is `observed_inventory_change`, `attributed_project_reduction` or `unknown`. Only observed change can supply source fitness. Causal/project/avoided-emission assertions remain insufficient even if an observed inventory declined. `quantity_interpretation` is `signed_change`, `decrease_magnitude` or `unknown`. A signed change compares the original literal value directly with current minus prior. For an explicitly selected decrease magnitude, a nonnegative original value is negated for comparison; its original text/value remains unchanged. A negative magnitude is unfit. Unknown direction is insufficient. This is a supplied semantic interpretation requiring qualified review; the helper does not infer the meaning of words such as lower, reduced or avoided.

An observed `-100 kg CO2e` change and an original stated decrease of `100 kg CO2e` can therefore match the same signed source with different explicit interpretations. A genuine increase conflicts with a decrease assertion. Percentage change uses the reproduced prior denominator; a zero prior gives an absolute change only. A missing percentage remains unknown, never zero or an invented ratio. Ranges, adjusted baselines, alternate denominators, intensity comparisons, annualization and project counterfactuals need additional methods.

Selected partial inventories may support qualified selected-source changes while all original gaps remain. Whole-subject claims additionally need an inventory criterion and reproduced declared coverage in both source inventories; one complete side cannot promote a partial other side. Facility/product attribution remains unavailable. Declared coverage, current source replay and arithmetic never verify external completeness, archived source authenticity, source rights, reviewer qualification or actual publication. Professional/jurisdiction/owner review and publication=false remain applicable.

`CLAIM_COMPARISON_SOURCE_CHECK` retains the prior snapshot, both full source bridges, the original comparison, explicit interpretations and false flags for project causation, avoided emissions, external completeness, authenticity and publication. `CLAIM_COMPARISON_INPUTS` retains the full parameters. Claims create no metric or stronger wording and preserve evidence, factors, past results, assumptions, gaps and reviews in a checked proposal.

The [fictional CLI evidence](../evaluations/sus20-comparison-claim.md) covers signed and magnitude statements, conflicting originals, causal interpretation and undefined percentage. Broader reduction attribution, product/test/intensity/future-plan methods, source/legal/rights/professional review, independent organization evaluation, individual skill interfaces, routing/skillsets and public-v1 readiness remain open. This increment does not close SUS-20 or the full roadmap goal.

Comparison criterion rows reference the single full `CLAIM_COMPARISON_SOURCE_CHECK` diagnostic by source-result ID and SHA-256 of its UTF-8 message (`json.dumps(proof, sort_keys=True)`). The complete paired proof remains in the same result. This avoids duplicating the prior snapshot/source graph in every criterion while retaining a checkable connection; earlier operation reports remain unchanged.

Quantity, baseline, comparability and whole-inventory criteria in this path must reference the selected reproduced comparison alone. A documentary-only baseline, unrelated source or mixed source list cannot supply a comparison criterion. Decrease polarity applies only to the selected comparison metric, preserving unrelated source values and original interpretations.
