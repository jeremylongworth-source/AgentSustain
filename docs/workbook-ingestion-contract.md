# Pinned literal workbook ingestion

`business-xlsx-ingestion-0.1.0` is a separate source reader alongside the unchanged CSV interface. Run `python -m scripts.run_workbook_ingestion REQUEST.json` with `ingest-business-records` in the common envelope. It emits a qualified `normalize-sustainability-data` result and append-only source/metric proposal; no Excel installation or added project dependency is required.

The format reference is [SpreadsheetML structure](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document) and [cell data/content representation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.cell), read as official documentation on 2026-10-06. Workbook/sheet relationships select parts, and cell types distinguish numeric and textual storage. This reader deliberately supports a bounded literal subset; it does not claim full Office/ISO conformance, native application compatibility or normative source rights. No reference-document content or source response bytes are redistributed.

## Exact selection and package limits

Parameters are `file_pin`, `source_metadata`, `sheet_name`, `fixture_mode`, `result_id`, `document_evidence_id`. Pin and source metadata use the CSV contract's explicit path/SHA/version/synthetic and title/publisher/accessed/tier fields. The selected file is an existing `.xlsx` within workspace `data/inputs/`, with at most 1 MiB original bytes. Traversal, escaping links, changed bytes and missing source/version/identity metadata block the import. Exactly one case-sensitive named visible worksheet is selected; other sheets remain outside demonstrated record coverage. Duplicate names/relationships or unresolved worksheet/shared-string parts are rejected.

The ZIP package has at most 64 distinct internal unencrypted stored/deflated members, 8 MiB total uncompressed data, 2 MiB per part and a maximum 200:1 member expansion ratio. Absolute/parent/drive/backslash member paths, unsupported compression and duplicate parts are rejected; nothing is extracted to filesystem. UTF-8 XML is parsed without DTD/entity declarations. Standard workbook root/relationship namespaces and XLSX content type are explicit; package defaults and exact overrides are supported. Macro-enabled types, VBA, external data/relationships, queries, embeddings and ActiveX are unsupported and never executed or followed.

The selected sheet is an unmerged literal table with exact business-record headers at `A1:Q1`, followed by 1-200 contiguous visible rows. Hidden rows/columns, row/column escapes, duplicate cell references, ambiguous value representations and selected drawing/extension/table/validation features are rejected. There is no automatic column/row/range/header interpretation, field extraction from bills, or partial record selection. Styles and displayed formats are recorded as cell style indexes and are not authority for numeric/date/unit inference.

## Literal cells and business semantics

Plain direct strings, shared strings and inline text preserve decoded text, cell address, OOXML type, original `v` literal and style index. Shared strings resolve only within the same bounded package. Numeric cells are accepted only for quantity and uncertainty-value fields; explicit decimal/scientific text in those fields is also supported by the existing decimal parser. All selected formulas are rejected even when cached results exist. Boolean/error/date cells, phonetic ambiguity and unsupported cell content are blocked. No formula engine, external refresh, application automation or calculation cache is used by ingestion.

ISO reporting-period fields are contractual text values. Numeric Excel date serials, styled dates, locale separators, unit display formats and labels are never converted into guessed source meanings. Blank quantity remains null with a gap; permitted zero and signed values remain literal for domain-specific review. Nonfinite/overflow/nonzero-to-zero underflow and invalid decimals are rejected. Exact original workbook cell literals remain in source snapshots; finite JSON representation does not promise arbitrary decimal precision.

Each record uses the unchanged seventeen CSV field names and explicit measurement/model/assumption/unknown kind, identity, unit, boundary, geography and uncertainty rules. Model/assumption records require substantive assumption text. Periods, kind declarations and source metadata remain attributed and unverified. Notes, including instructions to publish or remove review, are inert source data. No source/factor/GWP or organization-completeness fact is inferred.

## Evidence and rollback

A document evidence record binds the pinned workbook/version and declared selected-record period/units/geographies. Row evidence points to `workspace:<path>#sheet=<encoded-name>&row=N`, preserves its own quantity definition and references the document in lineage. Metrics directly reference their row evidence, retaining distinct physical cells. `WORKBOOK_ROW_SOURCE` stores full logical records, worksheet rows/cell addresses/types/literals, selected part, sheet names and exact package part hashes. `BUSINESS_INGESTION_INPUTS` preserves all parameters, including synthetic ancestry for downstream controls.

Any unsupported source/record/schema condition blocks the entire import. No partial new evidence, metrics, assumptions or source-review decisions survive rollback. Original state history, factors, gaps, uncertainty and review requirements remain unchanged. Successful imports stay partial, add professional source review and a source-fitness gap; byte identity is not publisher, measurement, model or organization authentication. The recognized shipped fictional workbook and identical byte copies cannot be relabeled ordinary inputs, and synthetic sources require explicit fixture opt-in. Other files' synthetic declarations remain unverified source metadata.
