# Plain-text claim material binding

`assess-bound-claim-evidence` adds explicit source-text binding to the initial claims reviewer. This draft `claim-evidence-0.2.0` execution interface requires scoped owner review after approved snapshot d99a70b. The existing `assess-claim-evidence` operation, saved requests and metadata-only material evidence remain unchanged.

The input retains the six existing claims parameters and adds `material_pin` (`path`, `sha256`) and `material_selectors` (`claim_span`, `qualification_spans`, `quantity_spans`). Invoke it through `python -m scripts.run_claims request.json` using the common input envelope. It returns a checked append-only state proposal and no quantitative metrics or publication authority.

Materials are bounded UTF-8 JSON files under `standards/claims/materials/`, with exact fields `id`, `version`, `synthetic`, `format`, `text`. Format must be `plain_text`; synthetic material requires explicit fixture mode. The selected evidence record must reference `workspace:standards/claims/materials/<path>` and the exact material version. Absolute or escaping paths, wrong bytes, incompatible source records and files over 128 KiB block before evidence assessment. Scoped LF checkout rules preserve fixture byte pins. Hash integrity establishes byte identity, not source authenticity.

Spans use nonempty, zero-based Unicode character offsets with an exclusive end. They refer to decoded `text`, not JSON-file byte offsets. The entire selected statement must equal the declared original wording without normalization or rewriting. Each qualification selector contains `text` and `span`; all declared qualifications must match actual characters. Other source text remains in the material snapshot. Undeclared qualifications and the statement's wider context still require qualified inspection; the helper does not infer completeness or meaning.

Each criterion with a numeric interpretation requires one distinct selector with `criterion_id`, `value_span`, `unit_span`. A literal value followed by its literal unit, separated only by whitespace, must occur inside the selected statement. The finite numerical value must equal `quantity.expected_value` and the unit must equal the criterion unit. Truncated numeric/unit tokens are rejected. This deliberately supports explicit literal quantities only; ranges, percentages with implied bases, calculated comparisons, locale-specific notation and implicit unit conversions need separate methods. Missing or mismatched bindings produce `CLAIM_MATERIAL_REQUIRED` with no assessment report or metric, preserving existing evidence, gaps and reviews. Unknown values never become zero.

Valid material binding then invokes the existing scoped evidence review. Reproduced quantities can conflict with the actual bound statement; a `99 kg CO2e` statement against a `0.14 kg CO2e` selected-source ledger becomes potentially misleading, without a legal finding. Binding the text `0.14` while declaring an interpretation of `99` instead blocks before review. Qualification presence cannot supply visibility or prominence: the separate supplied visibility observation remains necessary and unverified.

The assessment report stores the exact material, byte pin, evidence snapshot, selectors and bound text/quantities. `BOUND_CLAIM_INPUTS` retains complete inputs for later inspection. Integrity and exact-text flags are true; semantic interpretation, visual prominence, authorship/actual publication and source-authenticity flags remain false. Copied instructions inside a material are source data and confer no authority. Classification, judgment, method fitness and general impression remain supplied reviewer observations requiring qualified review.

The [fictional sequential evidence](../evaluations/sus20-bound-claim.md) demonstrates binding, blocked invented interpretation, actual conflicting material and unseen qualification, with original records and outstanding reviews preserved. It does not establish real publication provenance, full substantiation, actual jurisdiction applicability, whole-inventory neutrality, independent organization evaluation, SUS-20 completion or v1 readiness. No individual skill or active Canadian claims module is generated by this increment.
