# Climate-risk specialist composition

The draft `climate-workflow-0.1.0` composes fourteen existing physical/transition/exposure/register/priority/resilience operations through unchanged `run_climate` dispatch. [The skillset](../skillsets/climate-risk/SKILL.md) and [dependency inventory](../skillsets/climate-risk/manifest.json) reference exact entrypoint content reviewed through 7fff776. The new composition and its internal reference/result helpers do not inherit scoped owner approval or activate a production/router workflow.

Use the common input envelope with `skill=climate-risk` through `python -m scripts.run_climate_workflow request.json`. Exact parameters are `steps`, `outputs`, `workflow_review`, `result_id`. Each nonempty step is `{skill, parameters, depends_on}` with the existing climate operation's exact fields. Fresh step/aggregate IDs, distinct known prerequisites and an acyclic graph are mandatory. Input order breaks ties among ready branches. Unknown helpers, arbitrary code and recursive composition are unsupported.

Structured result selectors, driver selections and register/adaptation source lists must name freshly produced sources as ancestors. Metric selectors use their own namespace and actual produced-metric ownership is checked before execution. The collector reads schema-defined reference keys, not prose/source instructions. Current legacy sources retain their original method's reproduction and scope/scenario/horizon/source-fit checks. The workflow does not relabel a supplied proxy, mismatch or unreviewed driver as a scientifically validated source.

A blocked/invalid explicit prerequisite stops dependent invocation, preserving a common `CLIMATE_WORKFLOW_STEP_BLOCKED` result with exact inputs and original gaps/reviews. Independent branches can continue. Invoked domain input errors remain visible blocked results; invalid recipe/graph/source edges issue no candidate. Partial source results can enter downstream methods only with their own checks and retained limits. An all-blocked batch remains blocked.

`outputs` is a nonempty distinct selection of fresh recipe result IDs. `workflow_review` has exact `boundary_id`, `period`, `evidence_ids`, `scope`, `reviewer_role`, `rationale`, `coverage_complete`, matching current reporting state and resolving evidence. These are supplied observations, not authenticated reviewer authority or organization completeness. Incomplete coverage adds a gap, and a complete declaration never validates the model, populations, hazards or local risk outcomes.

`CLIMATE_WORKFLOW` retains dependency/invocation/status trace and exact result-hash views. Digests are SHA-256 of UTF-8 `json.dumps(result, sort_keys=True)`; complete source results/reports remain in candidate history. `CLIMATE_WORKFLOW_INPUTS` preserves the recipe. There is no new numerical aggregate or portfolio risk total. Original scenario, horizon, probability qualifiers, conditional stock shares, sensitivity/coping/adaptive definitions, ordinal uncertainty ranges, transition editions and prospective plan prerequisites remain separate in their source records.

One atomic candidate revision at original +1 preserves all evidence, factors, source/domain records, quantities, uncertainty, assumptions, gaps and reviews. An open professional climate/site review is added; none is resolved. Source authenticity, model validation, verified hazard probability, monetary loss quantification, organization safety, actual legal obligation, adaptation effectiveness, implementation and publication flags remain false. No physical asset, external service, source file or shared-state file changes.
