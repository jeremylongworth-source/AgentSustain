# Sustainable-procurement specialist

The draft `procurement-workflow-0.1.0` composes eleven existing supplier operations and three existing physical-carbon operations: CO2e calculation, Scope 3 classification and category composition. It uses unchanged core dispatch/formulas. [The skillset](../skillsets/sustainable-procurement/SKILL.md) and [dependency inventory](../skillsets/sustainable-procurement/manifest.json) reference actual entrypoints reviewed through 7fff776; this later specialist, including its internal reference/result helpers, does not inherit scoped approval or activate a router/production system.

Use the common envelope with `skill=sustainable-procurement` through `python -m scripts.run_procurement_workflow request.json`. Exact parameters are `steps`, `outputs`, `procurement_review`, `result_id`. Each nonempty step is exactly `{skill, parameters, depends_on}`, using the existing helper's exact fields. Optional fixture mode is explicit boolean and available only where the original helper supports it. Unknown operations, arbitrary scripts, recursive specialist composition and external actions are unsupported.

Step result IDs and aggregate ID are fresh and distinct. Dependencies name fresh step IDs and form an acyclic graph, ordered deterministically by input order among ready branches. Selected result references and known carbon-subtotal metric references must name their producing step as an ancestor. Metric and result namespaces stay separate; actual produced-metric ownership is checked again before execution. Planned subtotal metrics cannot collide with existing metrics or batch result IDs. Existing source references remain subject to the original method's current reproduction, scope/unit/evidence and service checks.

A blocked/invalid prerequisite prevents dependent helper invocation and records `PROCUREMENT_STEP_BLOCKED` with exact inputs and source/gap/review context. Missing factors propagate unchanged as `EMISSION_FACTOR_REQUIRED`; no contribution becomes zero. Independent branches continue, and supported partial sources remain qualified through downstream domain checks. Invoked helper input errors stay visible as blocked common results. Invalid graphs or source-producing edge selections issue no candidate. All-blocked batches remain blocked.

`outputs` selects a nonempty distinct list of freshly requested supplier/procurement results, not raw carbon leaves. `procurement_review` has exact `boundary_id`, `period`, `evidence_ids`, `scope`, `reviewer_role`, `rationale`, `coverage_complete`, matching validated buyer state and known evidence. These are attributed observations; declaring complete coverage never authenticates the supplier population, source fitness or review expertise. Incomplete declared coverage adds a gap.

`PROCUREMENT_WORKFLOW` records dependency/invocation/status trace, selected output IDs and source-result hash views. Each digest is SHA-256 of UTF-8 `json.dumps(result, sort_keys=True)`; every complete source result/report remains in candidate history. `PROCUREMENT_WORKFLOW_INPUTS` retains exact parameters. The aggregate emits no metric, combined portfolio total or selected supplier. Original source quantities, monetary scopes, ordinal rating bounds, unknowns, uncertainty and reviewer obligations stay in their own results. Structural custody is not source authentication, an environmental rating certification, actual harm verification, implemented reduction or purchasing permission.

The original-state candidate is atomic at revision +1, retaining every intermediate analytical/domain result and inherited evidence, factors, entities, assumptions, gaps and reviews. An open professional buyer review is registered; none is resolved. No supplier communication, order, actual engagement, procurement decision, publication or source/state-file write follows. [Fictional evidence](../evaluations/sus22-procurement-workflow.md) reproduces conditional 200/100 kg CO2e alternatives and supplied cost difference, plus fresh buyer assessments and unsent plans. Full supplier/value-chain coverage, broader scientific/risk/service applicability, independent behavioral/organization evaluation, scoped approval and remaining roadmap/v1 requirements remain open. This increment does not close SUS-22 or the full goal.
