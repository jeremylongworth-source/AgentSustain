# Reporting specialist contract

`reporting-workflow-0.1.0` composes nine existing carbon helpers and the two existing framework mapping/version-diff helpers without changing their calculations, source reproduction or catalog selection. The specialist name is `sustainability-reporting`. This later interface follows approved cd0c991 and awaits separate scoped owner review.

The common input envelope has `contract_version`, `skill`, `state`, `parameters`. Parameters are exactly `steps`, `outputs`, `reporting_review`, `result_id`. Every step has exactly `skill`, existing helper `parameters`, distinct `depends_on` result IDs. Carbon steps accept their existing exact required fields and optional boolean `fixture_mode`; mapping requires its existing explicit boolean fixture flag. There is no inherited fixture opt-in. Step/aggregate identities must be fresh, dependencies acyclic/resolvable and output selections freshly requested framework mappings or version differences.

`reporting_review` is exactly `boundary_id`, `period`, `evidence_ids`, `scope`, `reviewer_role`, `rationale`, `coverage_complete`, matched to state and attributed known evidence. Declared coverage does not authenticate sources or close other reviews. Typed current-result/metric sources use existing carbon selectors and the mapping inventory selector; prior comparison snapshots and catalog version pins remain separate. Planned subtotal identities and actual metric owners require explicit producing ancestors. Invalid recipes return no candidate; core input errors are visible blocked steps. Blocked prerequisites prevent dependent invocation while independent analyses continue.

Framework catalogs remain individually pinned by SHA-256 of actual selected bytes. Mapping replays full current inventory and scope/leaf source context. Historical GHG Protocol editions and TNFD referral context do not become current full authoritative coverage. Unsupported requirements, missing fields, unverified notes, omitted gas detail, partial scopes, source/rights limitations and qualified review remain in the original helper reports. Mapping-version differences retain both versions and never imply migration or fulfilled new requirements.

The specialist preserves complete original results and exact sorted-key JSON UTF-8 SHA-256 source views, with no aggregate metric or combined inventory total. Original state is unchanged. Candidate revision is original plus one after atomic composition; evidence, factors, source lineage, units, boundaries, periods, assumptions, uncertainty, gaps and open reviews remain. A professional reporting/source/rights/owner review is added. Missing-factor diagnostics survive composition and dependency skipping. Partial sources or coverage keep the aggregate partial; all blocked steps make it blocked.

Source authenticity, complete inventory coverage, active authoritative mapping, disclosure fulfillment, conformity, legal applicability and assurance remain unverified. Commercial reuse, public claims and publication remain unauthorized. A successful candidate, a declared complete review or a passing test cannot supply those judgments. The workflow does not infer factors, GWP, source authority, gas coverage or legal obligations.

The fictional controlled evaluations are author-led composition evidence. All seven named specialist roles now have initial implementations, but breadth of methods, current framework/Canada coverage, independent behavioral/organization acceptance, later scoped review and full public-v1/release criteria remain open. This increment does not close SUS-17, SUS-19, SUS-22 or the full roadmap.
